# SmartRoute Algorithmic Experiments Report

This document compiles the empirical results generated by the Benchmark Engine for the SmartRoute DAA Project.

## Experiment 1: Graph Search & Pathfinding (Point-to-Point)
**Objective**: Evaluate the trade-off between exact shortest-path algorithms and heuristics.
**Methodology**: 50 random source-target node pairs on the road network graph.

| Algorithm | Avg Distance (m) | Nodes Explored | Compute Time (ms) |
| :--- | :--- | :--- | :--- |
| **A\*** | 12762.49 | 363.24 | 1.81 |
| **Dijkstra** | 12762.49 | 1150.04 | 3.54 |
| **BFS** | 12762.82 | 1144.58 | 1.05 |
| **DFS** | 265914.91 | 1295.22 | 2.04 |
| **Greedy BFS** | 12763.79 | 33.84 | 0.25 |

**Analysis**: A* dramatically outperforms Dijkstra by reducing nodes explored by ~3x while guaranteeing the exact same mathematically optimal distance. Greedy Best-First Search is incredibly fast (0.25ms) but yields slightly suboptimal routes. DFS fails entirely to find reasonable routes in spatial graphs.

## Experiment 2: Route Sequencing (TSP with Pickup-Delivery Constraints)
**Objective**: Evaluate sequence optimization for a single driver's batch.
**Methodology**: Tested across batch sizes (4 to 10 stops).

| Stops | Algorithm | Avg Cost (Dist) | Compute Time (ms) |
| :--- | :--- | :--- | :--- |
| 10 | Greedy | 40.82 | 0.012 |
| 10 | 2-Opt (Local Search) | 37.30 | 0.141 |
| 10 | Held-Karp (DP) | 32.81 | 2.428 |

**Analysis**: As the batch size grows, the limitations of the Greedy approach become apparent (cost 40.82). The Held-Karp Dynamic Programming algorithm correctly identifies the global minimum (cost 32.81, an ~18% improvement), but at the cost of exponential time complexity ($O(N^2 2^N)$). The 2-Opt heuristic provides an excellent middle ground, improving the Greedy route by ~9% with very little compute overhead.

## Experiment 3: Driver-Batch Assignment (Bipartite Matching)
**Objective**: Evaluate the efficiency of global assignment vs local greedy choices.
**Methodology**: 50 idle drivers matching to 50 batches.

| Algorithm | Total System Distance | Compute Time (ms) |
| :--- | :--- | :--- |
| **Greedy (Nearest-Driver)** | 94.89 km | 3.61 |
| **Hungarian (Linear Sum)** | 76.07 km | 2.74 |
| **FoodMatch (Bounded Matching)**| 76.07 km | 2.75 |

**Analysis**: The Hungarian algorithm successfully minimizes the *global* system cost rather than getting trapped in local optima, saving nearly 20% in deadhead travel distance (94.89km down to 76.07km) across the fleet.

## Experiment 4: Order Batching Efficiency
**Objective**: Compare geographical clustering vs trajectory-based clustering.
**Methodology**: 100 pending orders.

| Algorithm | Total Batches | Avg Orders/Batch | Compute Time (ms) |
| :--- | :--- | :--- | :--- |
| **K-Means (scikit-learn)** | 43.7 | 2.29 | 42.72 |
| **FoodMatch (Graph Compatibility)** | 48.2 | 2.07 | 11.24 |

**Analysis**: The FoodMatch-inspired compatibility graph approach is highly computationally efficient (nearly 4x faster than K-Means). While K-Means forces slightly denser batches (2.29 vs 2.07), FoodMatch ensures batches are strictly formed on shared route trajectories (pickup *and* delivery proximity), which reduces severe detours during sequencing.
